You scoped an app to 50 mailboxes. It can still read all of them.

Darius Frank · October 2026

Exchange Online has a feature called RBAC for Applications. You grant an app a permission like Mail.Read, then limit it to a set of mailboxes. On paper it is clean least privilege: the app only touches the mailboxes you named.

The catch is that the Exchange grant does not replace the Mail.Read the app already holds as a tenant-wide Graph application permission in Entra. The two grants add together. Microsoft's own docs say the union results in no effective resource scoping. The scope you set in Exchange does nothing. The app reads every mailbox in the tenant.

I ran it to confirm

I tested this in my own tenant. I created an app, granted it Mail.Read tenant-wide in Entra, then added a scoped Application Mail.Read assignment in Exchange limited to two test mailboxes. The app could still read mail outside that scope. I removed the Entra grant, and only then did the Exchange scope actually bound it.

This is easy to miss because both grants look correct on their own. The Exchange side shows a tidy, scoped assignment. The Entra side shows a normal application permission. Nobody reviewing either one in isolation sees a problem. You have to look at both at once to catch that one cancels the other.

So I wrote a check for it

The check reads an app's Exchange RBAC assignments, maps each Exchange role to the Graph permission it corresponds to using Microsoft's documented table, and flags any app that holds the same permission, or a broader one, as a tenant-wide Graph grant. A broader grant counts too: Mail.ReadWrite tenant-wide swallows a scoped Mail.Read. If an Application Access Policy restricts the app, the check lists it for review instead of failing it, because that policy can still bound the access.

The check is MT.1252 in Maester, the open-source Entra and M365 security test framework. If you run Maester against your tenant, it tells you which apps are in this state. The pull request is maester365/maester #2506.

The fix is not in Exchange

Tightening the Exchange scope does nothing while the tenant-wide Graph grant is still there. You remove or narrow the Entra grant, then let the Exchange scope do its job.

If you have apps with mailbox access, this is worth ten minutes. Check whether the thing you scoped in Exchange is also sitting there unscoped in Entra.
